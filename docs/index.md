# ou_sdk Documentation

## Protocol documentation

- [Communication protocol v0.2.0 (auto-generated)](../generated/docs/protocol.md): the authoritative docs for the frame format, CRC, and payload definitions, generated by `tools/codegen.py` from `schema/protocol.yaml`.

> `schema/protocol.yaml` is the **single hand-written source of truth** for the three ends (host-station SDK, compute board, STM32 firmware). Every artifact under `generated/` is a derived result; do not edit it by hand.

## API reference

Generate the Doxygen docs:

```bash
doxygen docs/Doxyfile
```

Output goes to `build/doxygen/html/index.html`.

Coverage (the `INPUT` of `docs/Doxyfile`):

| Path | Description |
|------|------|
| `include/` | Hand-written public headers: `proto.hpp` (FrameParser / packet_traits / decode), `channel.hpp`, `udp_channel.hpp`, `serial_channel.hpp`, `frame_link.hpp` |
| `generated/ou/` | codegen-generated header: `protocol.hpp` (CmdPacket / TelemetryPacket / constants / encode / decode declarations) |

## Three-layer architecture

| Layer | Library | Responsibility |
|----|----|------|
| proto | `ou::proto` | Codec + stateful `FrameParser` streaming frame splitting |
| channel | `ou::channel` | Raw byte transport (`UdpChannel` / `SerialChannel`); no framing, no parsing |
| link | `ou::link` | Composition layer: `FrameLink` / `UdpFrameLink` / `SerialFrameLink`, providing `send_frame` / `recv_frame` / `recv_frame_as<Pkt>` type-safe receive |
